EinführungIntroduction

Vortex UI ist ein mit SvelteKit entwickeltes, anpassbares Dashboard für Home Assistant. Es ersetzt die HA-Standardoberfläche durch eine moderne, flüssige und flexibel konfigurierbare Benutzeroberfläche. Für die meisten Funktionen ist keine manuelle YAML-Konfiguration nötig.

Vortex UI is a custom dashboard for Home Assistant, built with SvelteKit. It replaces the default HA interface with a modern, fluid, fully configurable experience — no manual YAML required for most features.

Vortex UI basiert auf ha-fusion von amedello und ergänzt das Projekt um weitere Funktionen, darunter den Elementtyp Custom Panel, zusätzliche Themes, benutzerdefiniertes CSS in der App und weitere Verbesserungen.

This is a personal fork of the original ha-fusion by amedello, extended with additional features including the new Custom Panel item type, new themes, in-app custom CSS, and various improvements.

Installation – DockerInstallation — Docker

Installieren Sie Vortex UI mit Docker oder Docker Compose auf einem Linux-, macOS- oder Windows-Rechner, der Ihre Home-Assistant-Instanz im Netzwerk erreichen kann.

Use Docker (or Docker Compose) to install vortex-ui on any Linux, macOS or Windows machine with network access to your Home Assistant instance.

Erstellen Sie eine docker-compose.yml-Datei:

Create a docker-compose.yml file:

services:
  vortex-ui:
    container_name: vortex-ui
    image: ghcr.io/xsalegg/vortex-ui
    volumes:

      - "5050:5050"
    environment:
	TZ: Europe/Berlin        # Zeitzone
	HASS_URL: http://192.168.1.x:8123  # URL von Home Assistant
    restart: always

SchnittstellenübersichtInterface Overview

Die Vortex-UI-Schnittstelle besteht aus drei Hauptbereichen:

The vortex-ui interface consists of three main areas:

  1. Ansichtsleiste – oben werden Registerkarten für konfigurierte Ansichten angezeigt. Klicken Sie auf a Die Ansicht navigiert zu ihrem Inhalt.
  2. Views bar — at the top, shows tabs for configured views. Clicking a view navigates to its content.
  3. Hauptbereich – das zentrale Raster mit Abschnitten und Elementen. Nimmt den größten Teil davon ein den Bildschirm.
  4. Main area — the central grid with sections and items. Occupies most of the screen.
  5. Seitenleiste – links werden Informations-Widgets angezeigt (Zeit, Wetter, Sensoren usw.); auf kleinen Bildschirmen oberhalb der Navigation.
  6. Sidebar — shows informational widgets (time, weather, sensors, etc.) on the left; it moves above the navigation on small screens.

Menüsymbol (☰)Menu icon (☰)

Oben links befindet sich das Menüsymbol. Es öffnet die Seitenleiste mit globalen Optionen für Themes, CSS, Sprache, Einstellungen und Updates.

In the top left is the menu icon. It opens the Drawer containing global configuration options: themes, CSS, language, settings, and updates.

Schaltfläche „Bearbeiten“ (✏️)Edit button (✏️)

Oben rechts befindet sich die Schaltfläche zum Aktivieren des Bearbeitungsmodus. In diesem Modus werden Steuerelemente zum Hinzufügen, Verschieben und Konfigurieren von Elementen eingeblendet.

In the top right is the button to enter edit mode. In this mode all controls appear for adding, moving and configuring items.

Ansichten bilden die Hauptnavigation. Jede Ansicht kann beliebig viele Abschnitte enthalten. In YAML werden sie durch das views-Array am Anfang von dashboard.yaml definiert.

Views are the main navigation tabs. Each view can contain any number of sections. In YAML they correspond to the views array at the top of dashboard.yaml.

StandardansichtDefault View Neu

Sie können eine Ansicht als Standardansicht festlegen: das Dashboard kehrt nach einer gewissen Zeit der Inaktivität des Benutzers automatisch dorthin zurück. Nützlich zur Wandmontage Tablets, um das Dashboard immer wieder zur Hauptansicht zurückzubringen, wenn es unbeaufsichtigt bleibt.

You can designate one view as the default view: the dashboard automatically returns to it after a period of user inactivity. Useful on wall-mounted tablets to always bring the dashboard back to the main view when left unattended.

So konfigurieren SieHow to configure

Öffnen Sie im Bearbeitungsmodus die Konfiguration einer Ansicht (Zahnradsymbol) und legen Sie Folgendes fest:

In edit mode, open a view's configuration (gear icon) and set:

  • Standardansicht – aktiviert das is_default: true-Flag auf dem Ansicht.
  • Default view — enables the is_default: true flag on the view.
  • Rückkehr nach (Sekunden) – legt das Inaktivitäts-Timeout in Sekunden vorher fest Das Dashboard kehrt zu dieser Ansicht zurück ( default_timeout ).
  • Return after (seconds) — sets the inactivity timeout in seconds before the dashboard returns to this view (default_timeout).
HinweisNote — Der Inaktivitätstimer wird bei jedem Klick, jeder Berührung und beim Öffnen eines Dialogs zurückgesetzt. AbschnitteSections

Abschnitte organisieren Elemente innerhalb einer Ansicht. Es gibt vier Abschnittstypen.

Sections organise items within a view. There are four section types.

Normaler Abschnitt (Standard)Normal Section (default)

Der Grundtyp. Zeigt einen optionalen Titel und ein Raster mit Elementen an. In YAML ist es so kein type Feld.

The basic type. Shows an optional title and a grid of items. In YAML it has no type field. 

sections:
  - id: 1234567890000
    name: "Illuminazione"
    items:

        id: 9876543210001
		entity_id: light.wohnzimmer

Horizontal Stack

Platziert mehrere Abschnitte in horizontalen Spalten. Jede Spalte ist ein untergeordneter Abschnitt mit ihrem eigene Gegenstände. Ideal zum Aufteilen des Bildschirms in nebeneinander liegende Zonen.

Places multiple sections in horizontal columns. Each column is a child section with its own items. Ideal for splitting the screen into side-by-side zones. 

- type: horizontal-stack
  id: 1111111111111
  sections:
    - id: 2222222222222
      name: "Sinistra"
      items: # …
    - id: 3333333333333
      name: "Destra"
      items: # …

Vertical Stack Neu

Wie der horizontale Stapel, aber ordnet untergeordnete Abschnitte vertikal eins an übereinander. Jeder untergeordnete Abschnitt hat einen eigenen Titel. Nützlich für die logische Gruppierung verwandte Zonen in einer Spalte.

Like the horizontal stack, but arranges child sections vertically one above the other. Each child section has its own title. Useful for grouping logically related zones in a column. 

- type: vertical-stack
  id: 4444444444444
  sections:
    - id: 5555555555555
      name: "Piano terra"
      items: # …
    - id: 6666666666666
      name: "Primo piano"
      items: # …

Der vielseitigste Elementtyp. Ein Button kann jede Home-Assistant-Entität darstellen, etwa Lichter, Schalter, Skripte, Szenen, Klimageräte, Mediaplayer oder Sensoren. Bestätigungsdialog ( confirm )Confirmation dialog (confirm)

Bei confirm: true erscheint vor dem Ausführen des Umschalters ein Bestätigungsdialog oder individueller Service. Nützlich für kritische Aktionen (Alarm ausschalten, Tor öffnen, usw.). With confirm: true, a confirmation dialog appears before executing the toggle or custom service. Useful for critical actions (disarming the alarm, opening the gate, etc.). The gate applies to both the direct tile click and the Toggle switch inside the entity detail modal.

With show_timer: true on a tile whose entity is a timer.*, the text state is replaced by a live countdown in mm:ss format (or h:mm:ss for timers over an hour). The countdown updates every second and disappears automatically when the timer is idle.

Helligkeitsregler (ziehen)Brightness slider (drag)

Für helle-Entitäten können Sie die Helligkeit direkt auf der Kachel anpassen horizontal ziehen. Halten Sie die Kachel gedrückt und ziehen Sie sie dann nach rechts, um sie zu vergrößern, oder nach links, um sie zu vergrößern Helligkeit verringern. Eine farbige Überlagerung zeigt die aktuelle Ebene während des Ziehens an.

For light entities, you can adjust brightness directly on the tile by dragging horizontally. Press and hold on the tile, then drag right to increase or left to decrease brightness. A colour overlay shows the current level during the drag.

Benutzerdefinierter Dienst (Feld serviceCustom service (service field)

Wenn Sie anstelle des Standardschalters klicken möchten, um einen bestimmten Dienst auszuführen, verwenden Sie die service Feld. Der Wert ist ein mehrzeiliger YAML-String mit dem Dienst Struktur.

When you want click to execute a specific service instead of the default toggle, use the service field. The value is a multi-line YAML string with the service structure. 

- type: button

  name: "Soundbar"
  more_info: false

    service: remote.send_command
    data:
      device_id: abc123def456
      command: PowerToggle
      device: Soundbar

Vortex UI unterstützt drei Ebenen der bedingten Sichtbarkeit. Damit lassen sich Teile des Dashboards abhängig von Home-Assistant-Zuständen, Zahlenwerten oder der Bildschirmgröße ein- und ausblenden.

Vortex UI supports three levels of conditional visibility that let you show or hide parts of the dashboard based on HA states, numeric values or screen sizes.

1. Abschnittssichtbarkeit1. Section visibility

Legen Sie Bedingungen für den Abschnitt selbst fest. Der Abschnitt (und alle seine Elemente) werden ausgeblendet, wenn Bedingungen nicht erfüllt sind.

Set conditions on the section itself. The section (and all its items) is hidden when conditions are not met.

Konfigurierbar über die Schaltfläche Auge (👁) in der Abschnittsüberschrift im Bearbeitungsmodus.

Configurable via the eye (👁) button in the section header in edit mode.

2. Sichtbarkeit einzelner Elemente2. Single item visibility

Legen Sie Bedingungen für ein einzelnes Element fest. Werden sie nicht erfüllt, wird nur dieses Element ausgeblendet; die übrigen Elemente im Abschnitt bleiben sichtbar.

Conditions on a single item. Only that item is hidden when conditions fail; other items in the section remain visible.

Im Bearbeitungsmodus über die Schaltfläche Auge im Elementkonfigurationsdialog einstellbar.

Configurable via the eye button in the item configuration modal (edit mode).

3. Elementsichtbarkeitsvorlage3. Item visibility template Neu

Eine für den Abschnitt definierte Sichtbarkeitsbedingung, auf die automatisch angewendet wird alle Elemente im Abschnitt. Der spezielle Platzhalter {item.entity_id} wird vor der Auswertung durch die Entity_ID jedes Elements ersetzt Zustand.

A visibility condition defined on the section that is automatically applied to all items in the section. The special placeholder {item.entity_id} is replaced with each item's entity_id before evaluating the condition.

Konfigurierbar über die Schaltfläche scan-eye in der Abschnittsüberschrift.

Configurable via the scan-eye button in the section header.

      state_not: unavailable
